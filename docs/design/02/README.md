## 怎么读

- **引用而不复述**（P-06）：本文提到业务规则时只写编号，比如"派单（S-ORD-T08，R-DSP-*）"。
- **语言**：协议字段、枚举值、错误码、审计动作名一律用英文（F-UI-02）；说明用中文。
- **枚举值对照**：订单状态、打印机状态、标记的英文值见 [entities.md §2](entities.md#2-枚举)，和文档 1 的 `S-` 编号一一对应。
- **唯一来源**：
  - 实体字段：本文 entities.md。
  - 接口：openapi.yaml。
  - daemon 消息：重写时放进 `packages/shared/schema/` 的 JSON Schema（Q141），本文 daemon-protocol.md 是它的设计稿。
  - openapi.yaml 里的实体结构，重写时也挪进 `packages/shared/schema/`，改成 `$ref` 引用，和 daemon 消息共用一套（Q150）。
- **生成与检查**：服务端请求校验、前端客户端、Python 的 daemon 消息类型都从 Schema 生成，不手写第二份。CI 检查代码里的路由和 openapi.yaml 一一对应，每个接口都声明了权限节点（F-API-02）。

## 和现有代码的差异

代码会按本文重写（2026-11-04 决定），这里只列出差异，不在此修代码。

| 现有代码 | 本文 | 依据 |
| --- | --- | --- |
| 订单、版本主键是自增整数 | 一律 UUIDv7，订单另有给人看的编号 | Q140、E-ORD |
| `roles` 表 + `user_roles`（带 scope） | 角色是 `users.role` 一个枚举，权限矩阵写在代码里 | Q95、文档 0 §9 |
| daemon 用长期令牌认证 | 一次性注册令牌 + RSA-PSS 挑战签名 | F-DMN-01、F-DMN-02 |
| 失败归因、`retry_of` 等列 | 不存在 | F-PRT-07 |
| 打印机遥测是一个随意的 JSON | 快照有固定结构（MSG-SNAPSHOT） | Q142 |
| 设置是一张随意的键值表 | 每个分区一行，带版本号 | Q139、E-SET |
| 接口没有前缀版本 | `/api/v1` | F-API-01 |
| 写操作没有幂等键 | 所有写操作带 `Idempotency-Key` | Q138 |
| 停止请求可以撤销；已派单可以撤回 | 停止不能撤销；没有撤回，派单后不能取消和修改；命令只追踪送达，没有命令锁，按钮只看打印机上报的状态（Q243） | R-CMD、INV-16、Q203、Q207、Q215、Q243 |
