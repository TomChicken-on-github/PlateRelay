## 0. 怎么读

- **编号**：状态 `S-`，规则 `R-`，参数 `CFG-`。代码、测试、其他文档只引用编号，不复述内容（P-06）。
- **规则格式**：每条规则写五栏：触发、条件、结果、依据、参数（Q80）。"依据"引用文档 0 的 P / INV / F 编号；"参数"引用本文 §6。
- **"人"的说法**：申请者、现场人员、管理员、访客（未登录）。"现场人员及以上"= 现场人员和管理员。
- **系统不替人做决定**（P-03）：本文里凡是写"提醒"的地方，系统只提醒，不自动推进状态。

## 1. 术语

| 术语 | 含义 |
| --- | --- |
| 订单 | 一盘打印任务。多盘文件提交时拆成多个订单（INV-03），拆完互不关联。 |
| 版本 | 订单指向的一个不可变文件（INV-04）。修改文件 = 新增一个版本。 |
| 当前版本 / 待审版本 | 正在排队、会被打印的版本 / 已上传、等审核的新版本。 |
| 排序值 | 订单在队列里的位置依据，存下来的数字，不从提交时间重算（INV-10）。第一次审核通过时分配。 |
| 冻结 | 订单有排序值但暂时不能派单（修改待重审时）。位置保留，后面的单照常往前走。 |
| 派单 | 现场人员把一个排队中的订单发到一台空闲打印机（NG-07）。派单是一个动作，它产生一个打印任务。 |
| 打印任务 | 一次派单产生的一次打印尝试（E-JOB），有自己的阶段和结局（§4A）。重打、开打前停下后再派，都是新的打印任务，旧的留着。 |
| 映射 | 派单时把切片里的每个耗材对应到一个料位（以及热端）。只在派单时做，记在这次派单上（Q107）。 |
| 料位 | 打印机上能放一卷料的位置：AMS 槽或外挂料。 |
| 耗材目录 | 提交页"可用资源"里的耗材清单 = 自动行 + 库存行（Q116）。 |
| 自动行 / 库存行 | 自动行：开放给选手的打印机上当前装着的料，系统生成。库存行：管理员手动添加的"有这种料，要先换卷"。 |
| 标记 | 挂在打印机状态上的附加信息，不是状态（Q77）。订单显示它所在打印机的标记。 |
| 流程节点 | 订单时间线上固定的 6 个环节：提交、审核、排队、打印、入库、取件（Q146）。 |
| 记录 | 一次状态变化或一次有意义的操作，归到某个流程节点下。 |
| 备注 | 记录上附带的文字，分"选手可见"和"选手不可见"（Q121）。 |
| 对账 | daemon 重新连上后，用打印机上报的事实核对面板记录（P-02）。 |

## 4A. 打印任务（S-JOB）

打印机上报的事件先落到当前打印任务上，任务的阶段变化再按下面的映射表推动订单和打印机，三者在**同一个数据库事务**里改（Q218）。

**硬规则**：订单的已派单、打印中、失败、待入库，以及打印机**有当前任务时**的准备中、打印中、暂停中、待清板和任务结束后回到的空闲，只能经过映射表改，代码里不能直接写。暂停原因和"等待处理"标记也是映射的输出，同一个事务里一起改。订单状态仍然存在订单上，不是读的时候推算出来的。

不归映射表管的仍是打印机自己的转换：外部占用（R-PRT-11）、离线、空闲、维护中，以及待清板经入库或确认清板回到空闲（R-PCK-01、R-PCK-02、INV-12）。

### 4A.1 阶段

| 编号 | 阶段 | 说明 |
| --- | --- | --- |
| S-JOB-TRANSFERRING | 传文件 | 派单后，daemon 下载并上传文件，开打指令还没发（MSG-CMD-START） |
| S-JOB-PREPARING | 准备中 | 开打指令已发出（`job.staged`），或打印机报了准备中 |
| S-JOB-PRINTING | 打印中 | 打印机报告开始打印 |
| S-JOB-PAUSED | 暂停中 | 打印机报告暂停，带原因（R-PRT-03） |
| S-JOB-ENDED | 已结束 | 任务结束，带结局，不再变 |

阶段顺序：传文件 → 准备中 → 打印中 ⇄ 暂停中 → 已结束；传文件和准备中也可以直接到已结束。

结局：`FINISHED`（打完）、`FAILED`（开打后失败或停下）、`STOPPED_BEFORE_START`（开打前被停止，Q214）、`SEND_FAILED`（下发失败）、`START_FAILED`（开打前报错）、`NOT_ARRIVED`（现场判没到，R-CMD-04）。

### 4A.2 映射表

| 任务变化 | 订单 | 打印机 |
| --- | --- | --- |
| 新建（派单） | 已派单（S-ORD-T08） | 准备中（S-PRN-T03） |

人的判断也走这张表，来源记为现场人员：对账不一致时判失败或判打完（R-PRT-08），把任务结束为 `FAILED` 或 `FINISHED`（S-ORD-T13、T14）；"判为没到"（R-CMD-04）把任务结束为 `NOT_ARRIVED`。

- 结束照片、延时摄影、失败原因、跳过的零件、控制命令的锁，都挂在打印任务上（R-CAM-11、R-CAM-04、R-CMD）。
- 阶段不在面板上单独显示。唯一露出的地方是订单详情的"打印记录"：第 N 次、结局、结束照片。

### 5.13 命令（R-CMD）

面板经 daemon 发给打印机的命令分三类。**控制命令**会改变打印或机器状态：开打、停止、处理报错、跳过零件，以及设备控制里的暂停、继续、进退料、烘干、移轴。**设定值命令**是设备控制里"设成某个值"的那些：灯、温度、风扇、速度。**只读命令**不改变状态：刷新、开实况、抓拍、取延时摄影。每条命令都有送达期限（过期没送出就作废，文档 2 MSG-CMD-TTL）。

面板只追踪命令**送达**到哪一步（daemon 收到、已发给打印机、发送失败、过期），不逐条判断命令"执行了没有"（Q215）。订单和打印机的状态照旧只跟着打印机上报的事实走（P-01）；人拿不准时看摄像头判断。

| 编号 | 触发 | 条件 | 结果 | 依据 | 参数 |
| --- | --- | --- | --- | --- | --- |
| R-CMD-01 | 发出控制命令 | — | 点的按钮变灰并显示加载圆环（"已发送"）；同一台打印机其他控制按钮一起置灰 | P-01、Q215 | |

## 9. 设置页与管理页结构

只定结构，不定界面（Q128–Q133）。

### 9.1 系统设置

只放参数、开关和通知渠道配置，只有管理员能进。实体（一条条的东西）不放这里，见 §9.2。

| 分区 | 内容 |
| --- | --- |
| 通用 | 组织名、组织时区（F-OPS-07）、默认界面语言 |
| 界面 | CFG-UI-* |
| 摄像头 | CFG-CAM-* |
| 提交 | CFG-SUB-*（申请表单字段除外，见 §9.2） |
| 排队 | CFG-QUE-* |
| 修改 | CFG-REV-* |
| 映射 | CFG-MAP-*（规则参数；耗材目录见 §9.2） |
| 打印 | CFG-PRT-*、CFG-CMD-* |
| 取件 | CFG-PCK-* |
| 文件 | CFG-FIL-* |
| 账户 | CFG-ACC-*、人机验证方式 |
| 通知 | 渠道配置（SMTP、飞书）、CFG-NTF-01 各事件的默认开关 |
| 运维 | CFG-BAK-*、备份目录 |

- 每个参数只出现在一个分区。
- 每一项显示：名称、当前值、默认值、范围、生效时机（立即 / 新单）、"恢复默认"；和默认值不同的项要标出来。
- 按分区保存：保存前列出改前改后的对照，确认后生效，记审计；关联校验（如 CFG-MAP-04 > CFG-MAP-03）在保存时一起做（F-OPS-06）。
- v1 不做设置的导入导出（Q133）。

### 9.2 管理页

各自独立成页，不进系统设置。

| 页面 | 权限 | 内容 |
| --- | --- | --- |
| 打印机 | `printer:manage` | 添加（含自动发现，F-PRT-12）、编辑、删除；开放给选手开关需要 `resource:configure`。维护模式在打印机详情里，需要 `printer:maintenance` |
| daemon | `daemon:manage` | 生成安装命令、在线状态、版本、吊销（F-DMN-*） |
| 用户 | `user:manage` | 用户列表、角色、停用、邀请码 |
| 申请表单 | `form:configure` | 字段的增删改、排序 |
| 耗材目录 | `filament:catalog` | 库存行、自动行的隐藏 / 排序 / 备注；映射不符原因列表（CFG-MAP-05）需要 `resource:configure` |
| 审计日志 | `audit:view` | 只读查询 |

### 9.3 个人设置

每个登录用户都有，和系统设置是两个入口（Q132）：头像、显示名、界面语言、自己收哪些通知和走哪些渠道。"驳回"和"可取件"关不掉（R-NTF-02）。
