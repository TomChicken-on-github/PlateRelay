## 0. 怎么读

- **编号**：状态 `S-`，规则 `R-`，参数 `CFG-`。代码、测试、其他文档只引用编号，不复述内容（P-06）。
- **规则格式**：每条规则写五栏：触发、条件、结果、依据、参数（Q80）。"依据"引用文档 0 的 P / INV / F 编号；"参数"引用本文 §6。
- **"人"的说法**：申请者、现场人员、管理员、访客（未登录）。"现场人员及以上"= 现场人员和管理员。
- **系统不替人做决定**（P-03）：本文里凡是写"提醒"的地方，系统只提醒，不自动推进状态。

## 1. 术语

| 术语 | 含义 |
| --- | --- |
| 订单 | 一盘打印任务。多盘文件提交时拆成多个订单（INV-03），拆完互不关联。 |
| 版本 | 订单指向的一个不可变文件（INV-04）。修改文件 = 新增一个版本。 |
| 当前版本 / 待审版本 | 正在排队、会被打印的版本 / 已上传、等审核的新版本。 |
| 排序值 | 订单在队列里的位置依据，存下来的数字，不从提交时间重算（INV-10）。第一次审核通过时分配。 |
| 冻结 | 订单有排序值但暂时不能派单（修改待重审时）。位置保留，后面的单照常往前走。 |
| 派单 | 现场人员把一个排队中的订单发到一台空闲打印机（NG-07）。派单是一个动作，它产生一个打印任务。 |
| 打印任务 | 一次派单产生的一次打印尝试（E-JOB），有自己的阶段和结局（§4A）。重打、开打前停下后再派，都是新的打印任务，旧的留着。 |
| 映射 | 派单时把切片里的每个耗材对应到一个料位（以及热端）。只在派单时做，记在这次派单上（Q107）。 |
| 料位 | 打印机上能放一卷料的位置：AMS 槽或外挂料。 |
| 耗材目录 | 提交页"可用资源"里的耗材清单 = 自动行 + 库存行（Q116）。 |
| 自动行 / 库存行 | 自动行：开放给选手的打印机上当前装着的料，系统生成。库存行：管理员手动添加的"有这种料，要先换卷"。 |
| 标记 | 挂在打印机状态上的附加信息，不是状态（Q77）。订单显示它所在打印机的标记。 |
| 流程节点 | 订单时间线上固定的 6 个环节：提交、审核、排队、打印、入库、取件（Q146）。 |
| 记录 | 一次状态变化或一次有意义的操作，归到某个流程节点下。 |
| 备注 | 记录上附带的文字，分"选手可见"和"选手不可见"（Q121）。 |
| 对账 | daemon 重新连上后，用打印机上报的事实核对面板记录（P-02）。 |

## 2. 角色与权限

### 2.1 角色

| 角色 | 说明 |
| --- | --- |
| 访客 | 没登录的人。只在概况页公开时存在（F-UI-01）。 |
| 申请者 | 提交和管理自己的订单。 |
| 现场人员 | 派单、处理打印机、入库、核销、重打。 |
| 管理员 | 审核、排序、取消任意订单、所有配置。 |

- 每个用户只有一个角色；三个登录角色的权限按下表写死，不能给某个人单独加权限（Q95）。
- 最后一个管理员不能被删除或降级（INV-13）。
- 代码里现在还有 Builder / Coreteam 两个预设，按文档 0 Q12 合并为"管理员"。

### 4.2 标记

标记挂在打印机上，不改变状态；订单显示它所在打印机的标记（Q77）。

| 编号 | 标记 | 什么时候挂上 | 什么时候去掉 | 阻止派单 |
| --- | --- | --- | --- | --- |
| S-FLG-ATTENTION | 等待处理 | 报错暂停、断料、开打前报错（Q87）、对账不一致（Q93）、迟到的开打（R-PRT-17）、没清板就开打（R-PRT-11） | 问题处理完（打印机上报恢复，或现场人员处理）；任务结束时，这个任务运行中挂上的报错、断料一并去掉（Q226）；迟到的开打在那个迟到的任务结束时去掉。开打前报错是任务结束本身挂的，对账不一致和没清板就开打，都仍要现场人员处理 | ✓ |
| S-FLG-LOST | 失联 | 打印机不在空闲时 daemon 断线或连不上它（Q78、Q92、Q208） | 重新连上并对账完（R-PRT-07） | ✓ |
| S-FLG-STORAGE | 存储不足 | 剩余空间放不下下一个文件（F-PRT-11） | 空间够了 | ✓ |
| S-FLG-UPGRADE | daemon 需要升级 | 协议版本不兼容（F-DMN-05） | daemon 升级后重连 | ✓ |

每个标记都阻止派单，手动派单也一样，不只是系统建议（Q233）。以后新增标记必须在这一列写明阻止不阻止。

| S-PRN-T10 | 外部占用 | 待清板 | 外部任务结束。不论从空闲还是待清板进来，都回待清板，不回空闲（INV-01，Q225） |
| S-PRN-T11 | 待清板 | 空闲 | 铲件入库（INV-12）或确认清板 |
| S-PRN-T12 | 空闲、离线 | 维护中 | 现场人员或管理员开维护，填原因（Q94、Q148） |
| S-PRN-T13 | 维护中 | 空闲 | 现场人员或管理员关维护 |

失联不是状态：不在空闲时断线（包括待清板、维护中），打印机保留最后已知的状态，挂失联标记，重连对账前不能派单（Q92、Q208）。这样待清板、维护中不会因为断线被清掉（INV-01）。

## 4A. 打印任务（S-JOB）

打印机上报的事件先落到当前打印任务上，任务的阶段变化再按下面的映射表推动订单和打印机，三者在**同一个数据库事务**里改（Q218）。

**硬规则**：订单的已派单、打印中、失败、待入库，以及打印机**有当前任务时**的准备中、打印中、暂停中、待清板和任务结束后回到的空闲，只能经过映射表改，代码里不能直接写。暂停原因和"等待处理"标记也是映射的输出，同一个事务里一起改。订单状态仍然存在订单上，不是读的时候推算出来的。

不归映射表管的仍是打印机自己的转换：外部占用（R-PRT-11）、离线、空闲、维护中，以及待清板经入库或确认清板回到空闲（R-PCK-01、R-PCK-02、INV-12）。

### 4A.1 阶段

| 编号 | 阶段 | 说明 |
| --- | --- | --- |
| S-JOB-TRANSFERRING | 传文件 | 派单后，daemon 下载并上传文件，开打指令还没发（MSG-CMD-START）。这时被停止：daemon 中止传输、删掉自己传了一半的文件（INV-15）、保证不再发开打指令，回报已取消且没开打，任务以 `STOPPED_BEFORE_START` 结束，订单回原位。开打指令只有 daemon 发，所以这里以 daemon 为准（Q223） |
| S-JOB-PREPARING | 准备中 | 开打指令已发出（`job.staged`），或打印机报了准备中。打印机自己第一次报这个 jobRef 的准备中时记下时间（E-JOB `prepared_at`），"开打可能没到"（R-CMD-04）和对账（R-PRT-16）看的是它，不另设阶段（Q223） |
| S-JOB-PRINTING | 打印中 | 打印机报告开始打印 |
| S-JOB-PAUSED | 暂停中 | 打印机报告暂停，带原因（R-PRT-03）。准备阶段也可能暂停（进料失败、堵头、自检报错等，Q240）：任务记下是从准备中进来的，订单仍是已派单；这时停止仍算开打前停止（`STOPPED_BEFORE_START`），订单回原位 |
| S-JOB-ENDED | 已结束 | 任务结束，带结局，不再变 |

阶段顺序：传文件 → 准备中 ⇄ 暂停中、准备中 → 打印中 ⇄ 暂停中 → 已结束；传文件、准备中和准备阶段的暂停也可以直接到已结束。准备阶段的暂停恢复后回准备中，只有打印机真正报开打才进打印中（Q240）。

结局：`FINISHED`（打完）、`FAILED`（开打后失败或停下）、`STOPPED_BEFORE_START`（开打前停止，Q214）、`SEND_FAILED`（下发失败，包括对账判开打没到达打印机，R-PRT-16）、`START_FAILED`（开打前报错）。

### 4A.2 映射表

| 任务变化 | 订单 | 打印机 |
| --- | --- | --- |
| 新建（派单） | 已派单（S-ORD-T08） | 准备中（S-PRN-T03） |
| → 准备中 | 不变 | 不变 |
| → 打印中 | 打印中（S-ORD-T11） | 打印中（S-PRN-T04） |
| 准备中 → 暂停中 / 暂停中 → 准备中（准备阶段报错，Q240） | 不变（仍是已派单） | 仍是准备中，记暂停原因并挂等待处理，按 R-PRT-14 处理报错 / 去掉这次挂的等待处理 |
| 打印中 → 暂停中 / 暂停中 → 打印中 | 不变（暂停期间仍是打印中） | 暂停中并记暂停原因，报错和断料挂等待处理 / 打印中（S-PRN-T06、T07，R-PRT-03） |
| → 已结束 `FINISHED` | 待入库（S-ORD-T12） | 待清板（S-PRN-T08） |
| → 已结束 `FAILED` | 失败（S-ORD-T13） | 待清板（S-PRN-T08） |
| → 已结束 `STOPPED_BEFORE_START`、`SEND_FAILED`、`START_FAILED` | 排队中原位（S-ORD-T09） | 空闲（S-PRN-T05）；`START_FAILED` 另挂等待处理（Q87） |

任务结束（任何结局）时，同一个事务里去掉这个任务运行中挂上的等待处理（报错、断料），免得失败或停止后标记一直挂着、清完板也派不了单（Q226）。`START_FAILED` 是结束这一步才挂的，留给现场人员处理；对账不一致也照旧由人处理。

人的判断也走这张表，来源记为现场人员：对账不一致时判失败或判打完（R-PRT-08），把任务结束为 `FAILED` 或 `FINISHED`（S-ORD-T13、T14）。没有"判为没到"这种人工结局：开打可能没到时现场人员只能发停止，任务按打印机事实结束（R-CMD-04）。任务结束后打印机又报准备中或开打，不再挂回这个任务（R-PRT-17）。

- 结束照片、延时摄影、失败原因、跳过的零件、和任务有关的命令（开打、停止、跳过零件、处理报错），都挂在打印任务上（R-CAM-11、R-CAM-04、R-CMD）。
- 阶段不在面板上单独显示。任务不单独成页，v1 也没有跨打印机的任务列表（Q221）；只在两处露出：订单详情的"打印记录"（第 N 次、结局、结束照片），和打印机详情的"打印记录"（这台打印机最近的任务，最新的在前，每条带订单号、申请者、第 N 次、结局、开始和结束时间、结束照片，点开进订单）。申请者按通常的可见性规则显示（R-VIS）。

### 5.13 命令（R-CMD）

面板经 daemon 发给打印机的命令分三类。**控制命令**会改变打印或机器状态：开打、停止、处理报错、跳过零件，以及设备控制里的暂停、继续、进退料、烘干、移轴。**设定值命令**是设备控制里"设成某个值"的那些：灯、温度、风扇、速度。**只读命令**不改变状态：刷新、开实况、抓拍、取延时摄影。每条命令都有送达期限（过期没送出就作废，文档 2 MSG-CMD-TTL）。

面板只追踪命令**送达**到哪一步（daemon 收到、已发给打印机、发送失败、过期），不逐条判断命令"执行了没有"（Q215）。**没有命令锁**（Q243，参照拓竹 Bambu Studio 的做法）：按钮能不能点只看打印机上报的状态，按文档 2 IF-ADP-05 那张所有机型共用的表；固件回执失败时原样显示原因。订单和打印机的状态照旧只跟着打印机上报的事实走（P-01）；人拿不准时看摄像头判断。

| --- | --- | --- | --- | --- | --- |
| R-CMD-01 | 点控制按钮 | 按钮按打印机上报的状态可用（IF-ADP-05）：暂停只在打印中，继续只在暂停中，停止在准备中、打印中、暂停中 | 发命令；点的按钮转加载圆环，直到打印机上报的状态变了，最多 10 秒（前端常量，不进数据库、不做参数）。圆环停了按钮照上报状态显示，要不要再点由人看摄像头判断 | INV-16、P-01、Q215、Q243 | |

| --- | --- | --- |
| 打印机 | `printer:manage` | 添加（含自动发现，F-PRT-12）、编辑、停用 / 重新启用（R-PRT-20）、删除（只能删从没派过单的）；开放给选手开关需要 `resource:configure`。维护模式在打印机详情里，需要 `printer:maintenance` |
| daemon | `daemon:manage` | 生成安装命令、在线状态、版本、吊销（F-DMN-*） |
| 用户 | `user:manage` | 用户列表、角色、停用（R-ACC-05）、邀请码 |
| 申请表单 | `form:configure` | 字段的增删改、排序 |
| 耗材目录 | `filament:catalog` | 库存行、自动行的隐藏 / 排序 / 备注；映射不符原因列表（CFG-MAP-05）需要 `resource:configure` |
| 审计日志 | `audit:view` | 只读查询 |

打印任务不单独成页（Q221），见 §4A。

### 9.3 个人设置

每个登录用户都有，和系统设置是两个入口（Q132）：头像、显示名、界面语言、自己收哪些通知和走哪些渠道。"驳回"和"可取件"关不掉（R-NTF-02）。
