## 0. 怎么读

- **编号**：状态 `S-`，规则 `R-`，参数 `CFG-`。代码、测试、其他文档只引用编号，不复述内容（P-06）。
- **规则格式**：每条规则写五栏：触发、条件、结果、依据、参数（Q80）。"依据"引用文档 0 的 P / INV / F 编号；"参数"引用本文 §6。
- **"人"的说法**：申请者、现场人员、管理员、访客（未登录）。"现场人员及以上"= 现场人员和管理员。
- **系统不替人做决定**（P-03）：本文里凡是写"提醒"的地方，系统只提醒，不自动推进状态。

## 1. 术语

| 术语 | 含义 |
| --- | --- |
| 订单 | 一盘打印任务。多盘文件提交时拆成多个订单（INV-03），拆完互不关联。 |
| 版本 | 订单指向的一个不可变文件（INV-04）。修改文件 = 新增一个版本。 |
| 当前版本 / 待审版本 | 正在排队、会被打印的版本 / 已上传、等审核的新版本。 |
| 排序值 | 订单在队列里的位置依据，存下来的数字，不从提交时间重算（INV-10）。第一次审核通过时分配。 |
| 冻结 | 订单有排序值但暂时不能派单（修改待重审时）。位置保留，后面的单照常往前走。 |
| 派单 | 现场人员把一个排队中的订单发到一台可用的打印机（NG-07）。派单是一个动作，它产生一个打印任务。 |
| 打印任务 | 一次派单产生的一次打印尝试（E-JOB），有自己的阶段和结局（§4A）。重打、开打前停下后再派，都是新的打印任务，旧的留着。 |
| 映射 | 派单时把切片里的每个耗材对应到一个料位（以及热端）。只在派单时做，记在这次派单上（Q107）。 |
| 料位 | 打印机上能放一卷料的位置：AMS 槽或外挂料。 |
| 槽位克数 | 面板自己给每个料位记的剩余克数，换料时重置、任务结束时按用量扣（R-DSP-16、R-DSP-17）。不用打印机估的余量。 |
| 耗材目录 | 提交页"可用资源"里的耗材清单 = 自动行 + 库存行（Q116）。 |
| 打印板目录 | 本场每个机型能用哪些板型，由管理员在可用资源的机型编辑里勾选。只记"有没有"，不记块数，也不分装没装上（Q265）。v1 不做"板系列"（多机型通用的板），留给以后的资源管理（Q274）。 |
| 自动行 / 库存行 | 自动行：开放给选手的打印机上当前装着的料，系统生成。库存行：管理员手动添加的"有这种料，要先换卷"。 |
| 异常原因 | 打印机在"异常"状态的理由，可以同时有几个（§4.2，Q396）。v1 叫"标记"。订单显示它所在打印机的异常原因。 |
| 流程节点 | 订单时间线上固定的 6 个环节：提交、审核、排队、打印、入库、取件（Q146）。 |
| 记录 | 一次状态变化或一次有意义的操作，归到某个流程节点下。 |
| 备注 | 记录上附带的文字，分"选手可见"和"选手不可见"（Q121）。 |
| 对账 | daemon 重新连上后，用打印机上报的事实核对面板记录（P-02），只有三种结果（R-PRT-07）。 |
| 事件日志 | 一台打印机上报过的暂停、继续、报错、HMS 提示、联系不上和恢复的流水，只读（R-PRT-26）。 |

## 2. 角色与权限

### 2.1 角色

| 角色 | 说明 |
| --- | --- |
| 访客 | 没登录的人。只在概况页公开时存在（F-UI-01）。 |
| 申请者 | 提交和管理自己的订单。 |
| 现场人员 | 派单、处理打印机、入库、核销、重打。 |

- 最后一个管理员不能被删除或降级（INV-13）。
- 代码里现在还有 Builder / Coreteam 两个预设，按文档 0 Q12 合并为"管理员"。

## 4. 打印机状态机

第二稿把打印机状态从 8 个减到 4 个（Q396）。准备中、打印中、暂停中、子阶段都是**打印任务的阶段**（§4A），只作为进度显示，不再是打印机状态；原来的四种标记（等待处理、失联、存储不足、daemon 需要升级）合并成"异常"的原因（§4.2）。四个状态按"现场的人要做什么"来分：可用 = 能派单；工作 = 不用管；异常 = 要人去看；待清板 = 检查板子、确认后放行。

### 4.1 状态

| 编号 | 中文 | English | 说明 |
| --- | --- | --- | --- |
| S-PRN-AVAILABLE | 可用 | Available | 连着、没有任务在跑、板子已确认干净、没有异常原因。可以接单（还要看开放开关和停用，R-DSP-01）。 |
| S-PRN-WORKING | 工作 | Working | 在跑一个任务：系统派的（有当前打印任务，阶段见 §4A）或外部的（打印机报告在跑一个不是系统下发的任务，F-PRT-08）。人工暂停也还是工作。 |
| S-PRN-ATTENTION | 异常 | Needs attention | 有至少一个异常原因（§4.2）。可能还挂着一个当前任务，任务照常按打印机事实推进。 |

打印机上报的原始状态（准备中、打印中、暂停及原因、子阶段、HMS 提示）照常显示在卡片和详情上（R-VIS-11），也记进这台打印机的事件日志（R-PRT-26）；它们不改变上面这四个状态，除非下表写明。

### 4.2 异常原因

一台打印机可以同时有几个原因，每个单独记一条；有任何一条就是异常，全部去掉才离开异常（Q315 的合并显示保留：界面上一个"异常"，点开列出全部原因）。异常的打印机不能派单，手动派单也一样（Q233）。

| 编号 | 原因 | 什么时候挂上 | 什么时候去掉 |
| --- | --- | --- | --- |
| S-RSN-OFFLINE | 联系不上 | daemon 断线（MSG-HB-02），或 daemon 报连不上这台打印机（MSG-HB-03）。不论打印机原来在什么状态，空闲时断线也算（Q399） | 重新连上并按 R-PRT-07 对完账 |
| S-RSN-ERROR | 报错或断料 | 打印机报告因报错或断料暂停（准备阶段的暂停也算，Q240），或报了 HMS 错误级提示需要人处理 | 打印机报告恢复，或这个任务结束（Q226） |
| S-RSN-MAINT | 维护 | 现场人员或管理员手动挂上，必须填原因（Q94、Q148） | 挂它的那类人手动去掉 |
| S-RSN-JUDGE | 待判定 | 对账时这个任务既没在跑、也没有明确结局（R-PRT-08），或"开打可能没到"停止后给不出事实（R-CMD-04） | 现场人员三选一判定（R-PRT-08） |
| S-RSN-SEND | 下发失败 | 任务以下发失败结束（daemon 重试后仍传不上，比如打印机存储放不下，Q400） | 现场人员看过后手动去掉 |
| S-RSN-UPGRADE | daemon 需要升级 | 协议版本不兼容（F-DMN-05） | daemon 升级后重连 |

存储快满时拓竹的 HMS 信息级提示只是提示，照常显示在打印机上，不是异常原因、不挡派单（Q400）。以后新增原因都按这张表加一行。

## 4A. 打印任务（S-JOB）

打印机上报的事件先落到当前打印任务上，任务的阶段变化再按下面的映射表推动订单和打印机，三者在**同一个数据库事务**里改（Q218）。

**硬规则**：订单的已派单、打印中、失败、待入库，以及打印机因任务进出工作、待清板和 S-RSN-ERROR、S-RSN-JUDGE、S-RSN-SEND 三种原因，只能经过映射表改，代码里不能直接写。订单状态仍然存在订单上，不是读的时候推算出来的。

不归映射表管的是打印机自己的转换：外部任务（R-PRT-11）、联系不上、维护、需要升级，以及待清板经入库或确认清板回到可用（R-PCK-01、R-PCK-02、INV-12）。

### 4A.1 阶段

| 编号 | 阶段 | 说明 |
| --- | --- | --- |
| S-JOB-TRANSFERRING | 传文件 | 派单后，daemon 下载并上传文件，开打指令还没发（MSG-CMD-START）。这时被停止：daemon 中止传输、删掉自己传了一半的文件（INV-15）、保证不再发开打指令，回报已取消且没开打，任务以 `STOPPED_BEFORE_START` 结束，订单回原位。开打指令只有 daemon 发，所以这里以 daemon 为准（Q223） |
| S-JOB-PREPARING | 准备中 | 开打指令已发出（`job.staged`），或打印机报了准备中。打印机第一次报这个 jobRef 的准备中时记下时间（E-JOB `prepared_at`），"开打可能没到"（R-CMD-04）看的是它 |
| S-JOB-PRINTING | 打印中 | 打印机报告开始打印 |
| S-JOB-PAUSED | 暂停中 | 打印机报告暂停，带原因（R-PRT-03）。准备阶段也可能暂停（Q240、Q310）：任务记下是从准备中进来的，订单仍是已派单；这时停止仍算开打前停止（`STOPPED_BEFORE_START`），订单回原位 |
| S-JOB-ENDED | 已结束 | 任务结束，带结局，不再变 |

阶段顺序：传文件 → 准备中 ⇄ 暂停中、准备中 → 打印中 ⇄ 暂停中 → 已结束；传文件、准备中和准备阶段的暂停也可以直接到已结束。准备阶段的暂停恢复后回准备中，只有打印机真正报开打才进打印中（Q240）。

结局：`FINISHED`（打完）、`FAILED`（开打后失败或停下）、`STOPPED_BEFORE_START`（开打前停止，Q214）、`SEND_FAILED`（下发失败）、`START_FAILED`（开打前报错）。

### 4A.2 映射表

| 任务变化 | 订单 | 打印机 |
| --- | --- | --- |
| 新建（派单） | 已派单（S-ORD-T08） | 工作（S-PRN-T20） |
| → 准备中、准备中 ⇄ 暂停中、打印中 ⇄ 暂停中 | 不变 | 不变。报错和断料暂停挂 S-RSN-ERROR（→ 异常，T22），打印机报恢复时去掉（→ 工作，T23）；人工暂停（`USER`）不挂，给"继续"按钮（IF-ADP-05） |
| → 打印中 | 打印中（S-ORD-T11） | 不变 |
| → 已结束 `FINISHED` | 待入库（S-ORD-T12） | 待清板（T21） |
| → 已结束 `FAILED` | 失败（S-ORD-T13） | 待清板（T21） |
| → 已结束 `STOPPED_BEFORE_START`、`START_FAILED` | 排队中原位（S-ORD-T09） | 待清板（T21） |
| → 已结束 `SEND_FAILED` | 排队中原位（S-ORD-T09） | 挂 S-RSN-SEND（异常，T22） |

任务结束时，同一个事务里去掉这个任务挂上的 S-RSN-ERROR 和 S-RSN-JUDGE（Q226、Q359）。打印机还有别的原因（如联系不上、维护）时留在异常，原因全清空后按 T23 / T24 走。结束时打印机正在跑别的任务的，进工作（外部），不进待清板。

人的判断也走这张表，来源记为做判定的人：现场人员三选一判失败、判打完或判没开打（R-PRT-08，Q360），把任务结束为 `FAILED`、`FINISHED` 或 `STOPPED_BEFORE_START`（S-ORD-T13、T14、T09）。判没开打时面板同时给 daemon 发 `job.stop`，让它记下这个任务不再开打。任务结束后打印机又报这个 jobRef 在准备或开打，按外部任务处理（R-PRT-11），不挂回这个任务（Q393）。

- 结束照片、延时摄影、失败原因、跳过的零件、和任务有关的命令（开打、停止、跳过零件、处理报错），都挂在打印任务上（R-CAM-11、R-CAM-04、R-CMD）。
- 阶段不单独成页。任务不单独成页，v1 也没有跨打印机的任务列表（Q221）；只在两处露出：订单详情的"打印记录"（第 N 次、结局、结束照片），和打印机详情的"打印记录"（这台打印机最近的任务，最新的在前，每条带订单号、申请者、第 N 次、结局、开始和结束时间、结束照片，点开进订单）。申请者按通常的可见性规则显示（R-VIS）。

### 5.13 命令（R-CMD）

面板经 daemon 发给打印机的命令分三类。**控制命令**会改变打印或机器状态：开打、停止、处理报错、跳过零件，以及设备控制里的暂停、继续、进退料、烘干、移轴。**设定值命令**是设备控制里"设成某个值"的那些：灯、温度、风扇、速度。**只读命令**不改变状态：刷新、开实况、抓拍、取延时摄影。每条命令都有送达期限（过期没送出就作废，文档 2 MSG-CMD-TTL）。

面板只追踪命令**送达**到哪一步（daemon 收到、已发给打印机、发送失败、过期），不逐条判断命令"执行了没有"（Q215）。**没有命令锁**（Q243，参照拓竹 Bambu Studio 的做法）：按钮能不能点只看打印机上报的状态，按文档 2 IF-ADP-05 那张所有机型共用的表；固件回执失败时原样显示原因。订单和打印机的状态照旧只跟着打印机上报的事实走（P-01）；人拿不准时看摄像头判断。

## 10. 第二稿的变化

2026-11-10 做减法（Q378–Q403）。判据写在文档 0 P-05：只为罕见且不致命的情况存在的自动规则砍掉，交给人；防止事故的规则不砍。

**打印机状态（Q396–Q399、Q402、Q403）**

- 打印机只有四个状态：可用、工作、异常、待清板（§4.1）。准备中、打印中、暂停中是任务阶段（§4A）。
- 四种标记并成异常原因（§4.2）：联系不上（含空闲时断线，Q399）、报错或断料、维护、待判定、下发失败、daemon 需要升级。
- 工作结束和异常解除一律进待清板，只有打印机报恢复打印才从异常直接回工作（S-PRN-T23）；维护就是一个异常原因。
- 对账只剩三种结果（R-PRT-07）：同一任务还在进行就接着走；有明确结局就按事实；其他交给人判（S-RSN-JUDGE）。
- 现场人员可以放出异常的打印机，有任务时当场三选一（R-PRT-27），替代管理员的强制收回和状态自检。
- 新增打印机事件日志（R-PRT-26）。

**删掉的规则和参数**
