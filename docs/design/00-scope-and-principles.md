## 1. 定位

**一句话**：面向多方共享打印资源的 3D 打印工作流系统。申请者提交切好片的文件，经人工审核、排队、打印、铲件入库，再凭码取件。申请者全程不接触打印机。

**目标场景**：黑客松、创客空间、学校、工作室。一套部署服务一个组织，既可以长期运行，也可以用来办一场短期活动。

**和打印农场系统的区别**：

| | 打印农场系统 | PlateRelay |
| --- | --- | --- |
| 设备归属 | 单一组织私有 | 多方共享的公共资源 |
| 谁来排产 | 管理员内部决定 | 默认先到先得，规则公开、可审计 |
| 提交者 | 内部人员 | 外部申请者，不接触设备 |
| 额外环节 | 无 | 人工审核、铲件入库、扫码取件 |

## 3. 取舍顺序

规则冲突时，按下面的顺序决定谁优先：

1. **设备与人身安全**
2. **数据正确**：不丢单、不错发、不错取
3. **公平**
4. **现场效率**
5. **功能丰富**

**公平的定义**：默认先进先出。人工保留最终调整权，可以拖拽调整排队顺序，不逐条列举特殊情况。人工调整照常记审计日志，不对申请者公开（简报 §0.6）。

## 4. 设计原则

| 编号 | 原则 |
| --- | --- |
| P-01 | **只有打印机确认的事实，才能让系统进入不可逆状态。** 比如点了停止，只进入"停止请求中"，打印机确认停下后才记为已停止。 |
| P-02 | **物理状态以打印机上报为准，业务状态以面板为准。** 两边不一致时，按打印机上报对账。 |
| P-03 | **系统不确定时不替人做决定。** 失联、外部任务等情况下，系统只标记、提醒、等待对账，不自动判失败、不自动退回队列、不去停机。 |
| P-04 | **参数修改只对之后发生的事件生效，不回溯重算。** 唯一的例外是安全限值，派单时按当前值复核（INV-11）。 |
| P-05 | **简单优先。** 罕见情况交给人工处理，不为它新增状态或功能。 |
| P-06 | **每条规则只在一处定义并编号。** 其他文档、代码、测试只引用编号，不复述内容。 |
| P-07 | **核心流程不依赖某个品牌。** 品牌特有的东西（拓竹的 AMS、HMS、跳过零件）一律走适配器的能力声明。 |

## 5. 不变量

任何时候、任何配置下都必须成立。没有开关可以关掉这些条目。

| 编号 | 不变量 |
| --- | --- |
| INV-01 | 打印机必须有人确认"已铲件、已清板"，才能接下一单。能自动清板的机型由适配器声明这项能力，不靠设置开关。 |
| INV-02 | 一台打印机同一时间最多只有一个活跃的打印任务。 |
| INV-03 | 一单一盘。多盘文件提交时自动拆成独立订单，拆分后每单完全独立。 |
| INV-04 | 订单只指向不可变的文件版本。开始打印后不能再改文件。 |
| INV-05 | 一个订单只能核销一次。核销、取消、重打都会让取件码失效。 |
| INV-06 | 审计日志只追加，不修改、不删除，永久保留。 |
| INV-07 | 凭据（打印机访问码、令牌、私钥）不进代码、配置文件、日志、命令行参数，也不从任何接口返回。daemon 私钥不离开本机。 |
| INV-08 | "品牌 + 序列号"唯一对应一台打印机；驱动之外只认打印机 UUID。序列号变化视为一台新打印机。 |
| INV-09 | 一台打印机同一时间只被一个 daemon 认领。换 daemon 接管需要管理员确认。 |
| INV-10 | 队列顺序由存储下来的排序值决定，不从提交时间重算。 |
| INV-11 | 文件安全校验通过才能提交订单；派单时按当前安全限值对选中的打印机复核。结构损坏和危险指令一律拒收，不能配置。 |
| INV-12 | 铲件入库是一个动作：订单入库和打印机放行在同一个事务里完成（简报 §0.2）。 |
| INV-13 | 系统里至少保留一个管理员，最后一个管理员不能被删除或降级。 |
| INV-14 | 控制命令只能是白名单里的命令，白名单之外的命令 daemon 一律拒绝执行。 |
| INV-15 | daemon 只能删除打印机里由它自己放入或下载过的文件，不碰任何其他文件。 |
| INV-16 | 一台打印机发出控制命令后，在打印机上报状态变化或过了确认期限之前，不能再发别的控制命令（包括反向命令和再发一次）；设定值命令不算，停止例外（文档 1 R-CMD，Q215）。同一条命令（同一个命令 ID）的投递重试不算再发，daemon 保证同一条命令最多执行一次。 |

### 6.3 打印与设备

| 编号 | 内容 | 去向 |
| --- | --- | --- |
| F-PRT-01 | 拓竹适配器，在 pybambu 外再包一层；pybambu 的类型不越过拓竹驱动 | ② |
| F-PRT-02 | 适配器接口在纸面上对照 Moonraker 检查一遍，映射不了的降级为可选能力 | ② |
| F-PRT-03 | 流程命令：派单开打、停止、处理报错（只能选打印机给出的选项）、跳过零件 | ①② |
| F-PRT-04 | 设备控制（速度、风扇、灯、温度、进退料、烘干、暂停/继续、移动轴）：单独权限，默认给现场人员和管理员；适配器只声明静态命令清单，面板按通用状态规则限制，固件拒绝时原样回报；速度、风扇、灯、温度按设定值下发，不受 INV-16 的锁限制，界面显示打印机上报的值 | ①② |
| F-PRT-05 | 停止打印：选原因、二次确认后进入"停止请求中"，打印机确认后才算停止（P-01）。底层一律是一次停止命令。已派单但还没开打时停止，不算失败，订单回到队列原位置 | ①③ |
| F-PRT-06 | 可恢复的中断不算失败：打印机进"暂停中"并记原因（人工暂停、报错、断料）；报错和断料再挂"等待处理"标记 | ① |
| F-PRT-07 | 重打：打印机确认终止 → "失败"。重打只用于打印机或现场一方的问题；选手模型本身的问题由选手提交新订单，不做"失败后修改"（Q224）。从"失败"出发现场人员有两个操作：点"重打"，订单回到排队中，用原排序值，版本、文件、修改次数全部不变，文件已过期时"重打"按钮置灰并说明原因，现场人员请申请者重新提交；归档过的失败订单也不能重打。或者点"不重打，请选手重新提交"，必须填原因（默认选手可见），订单仍是失败，重打按钮隐藏，申请者收到通知；管理员可以撤销，恢复重打。不点就停在"失败"，失败是结果，不能取消。申请者没有重打按钮，想再打就正常提交新订单，系统不做关联和拦截 | ① |
| F-PRT-08 | 外部发起的打印标记为"外部占用"，不派单、不停机，打完照样要清板 | ①③ |
| F-PRT-09 | 摄像头实况：能看到打印机的地方就能看实时画面（适配器能力），实时优先于分辨率。**按需推流**：卡片平时显示定时抓拍，有人点播放才拉流，最后一个观众离开一段时间后断开。每台打印机 daemon 只拉一路流、不转码，单独转给面板（不走 daemon 和面板之间的控制通道），由面板分发给所有观众，浏览器不直连打印机。每台打印机的观看人数、场地同时推流的打印机数都有上限（可配置），超出的人看抓拍。"访客可看实况"开关默认关。实况拿不到时（机型不支持、流断开、超出上限）改为显示定时抓拍。抓拍也按需：有人在看时拍得勤，没人看时几分钟一张，各台错开时间、排队上传，避免同时占满场地上行；面板只在内存里留每台最新一张，不长期保存。例外是结束照片：打印机报告打完、失败或停止时立刻拍一张，每次派单一张，永久保留（文档 1 R-CAM-11，Q217）。看实况和抓拍都只读摄像头，不发任何控制命令 | ①② |
| F-PRT-10 | 延时摄影：使用打印机自带的录制（适配器能力，不支持的机型没有）；打印结束后 daemon 通过 FTPS 下载、上传到对象存储，核对大小和哈希无误后删除打印机里的这一个原文件；只有订单本人、现场人员、管理员能看，概况页不显示；和模型文件一起过期，保留天数可单独配置；不转码，走短期签名链接，每次查看记审计日志。另外，打完、失败或停止时自动拍一张结束照片，每次打印一张，永久保留，订单本人、现场人员、管理员可见（Q217、Q222） | ①② |
| F-PRT-11 | 打印机存储管理：daemon 只删除自己放进去或下载过的文件（记录在清单里），任务结束后删除它下发的 3mf；用户自己拷入的文件一律不碰；剩余空间不够放下一个文件时，这台打印机不出现在派单选项里，并提醒现场人员 | ①② |
| F-PRT-12 | 打印机自动发现（适配器能力）：daemon 被动监听局域网广播（拓竹为 SSDP），只听不发。面板"添加打印机"列出听到的机器，由人点选并填写访问码，不自动加入；听不到时只显示"没有发现"，手动填 IP 始终可用。同一序列号换了 IP 时自动更新地址并记审计。已由另一个 daemon 管理的打印机只做标记，管理员要在打印机设置里明确移过去 | ①② |

### 6.5 daemon

| 编号 | 内容 | 去向 |
| --- | --- | --- |
| F-DMN-01 | 只能从面板生成安装命令（参照 Komari agent），命令只带一次性注册令牌（15 分钟有效、用过即作废） | ②③ |
| F-DMN-02 | 每个 daemon 一对 RSA-3072 密钥：加密访问码（RSA-OAEP）和连接认证（RSA-PSS 挑战签名）共用；面板只存公钥 | ② |

| F-DMN-04 | 心跳超时 → 打印机"失联" → 重连后对账（P-02、P-03） | ①③ |
| F-DMN-05 | 协议版本协商，面板兼容上一个大版本的 daemon；不兼容时进入"需要升级" | ② |
| F-DMN-06 | 支持 Linux（含树莓派，systemd）、Windows（Windows 服务）、Docker（host 网络） | ② |
| F-DMN-07 | 升级：面板显示版本并给出升级命令，由人执行；安装包校验签名或哈希 | ② |

## 7. v1 不做（推后）

- 延时摄影转码
- 其他品牌的驱动（Moonraker、Prusa），纯 `.gcode` 解析
- 个人访问令牌、Webhook
- 配额与计费
- macOS 版 daemon
- 角色编辑器
- 零停机升级、HTTP 轮询备用通道
- daemon 自动升级
- "他人正在审核"锁
- 合并取件

## 8. 以后再说

- 库存管理（耗材卷识别、余量估算）
- 基于策略接口的真正配额
- 自动派单、自动开打（一个额外开关）
- 轻微修改自动审核（同机型、同材质、时长变化在阈值内免审）
- 多租户、按房间或场次隔离权限

以后要开放个人访问令牌时，以下权限节点永远不能授权给令牌：设备控制、用户与角色管理、系统设置、查看审计日志、daemon 注册、备份与恢复。
