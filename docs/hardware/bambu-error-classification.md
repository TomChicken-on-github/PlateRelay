# 拓竹打印机报错分类：哪些能避免、哪些能自动处理、哪些必须人处理

> 全文都是【建议】，还没有经用户确认。覆盖拓竹官方表里的全部 14 个机型前缀；§2 到 §4 的示例码取自 X2D，规则对所有拓竹机型通用。其他品牌暂不定。本文是独立的参考文档，不引用、也不改动设计层文档（00 到 03）的规则；设计层要采用其中哪些，由那边自己决定。

## 0. 先看规模

### 0.1 拓竹全部机型

拓竹按**序列号前 3 位**分报错表，driver 用打印机自己的序列号挑表，不用知道型号名。

- 7 个前缀随 Bambu Studio 开源打包在 `resources/hms/`：`093` `094` `20P`（X2D，实测确认）`22E` `239` `26A` `31B` `32X`。
- 老机型的表不在仓库里，Bambu Studio 运行时从 `https://e.bambulab.com/query.php?lang=en&d=<前缀>` 下载，按钮表从 `https://e.bambulab.com/hms/GetActionImage.php?d=<前缀>` 下载（见 Bambu Studio `HMS.cpp`、`AppConfig.cpp`）。这次下载了 `00M` `01P` `01S` `030` `039` `03W`。daemon 应该把这些表随驱动内置，不要运行时去拓竹云取（局域网部署可能没外网，也不该依赖云）。
- 前缀和型号的对应只有 `20P` = X2D 是实测确认的，其余没有官方对照表，这里不猜。

| 前缀 | 00M | 01P | 01S | 030 | 039 | 03W | 093 | 094 | 20P | 22E | 239 | 26A | 31B | 32X |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `print_error` 码数 | 490 | 470 | 470 | 499 | 500 | 492 | 630 | 651 | 837 | 595 | 704 | 566 | 840 | 1204 |

- 14 个前缀合起来 1776 个不同的码。**有 258 个码在不同机型上文案不同，16 个码的分类因机型而变**。例如 `03008013` 在部分机型上是「用户暂停」，在 X2D 等机型上是「切片文件里加的暂停命令」（通常是换料暂停，要人处理）。所以 driver 必须按打印机自己的前缀查表，不能用一张合并表。
- 全部码的逐条分类在 [`bambu-error-classification.csv`](bambu-error-classification.csv)，每行是「码 + 文案」，带适用的前缀和官方按钮。分类是按文案关键词自动打的，再人工修正了明显错的（云端连接被误判成安全、「AMS 断开，重连后自动继续」改成要人处理），**没有逐条人工审过**，用到具体码时以这里的规则和官方文案为准。

| 只记录 | 6 |
| 安全告警 | 21 |

### 0.2 X2D 单机型的情况

- `device_error`（对应上报里的 `print_error`，8 位码）共 853 条。把 AMS 编号、槽位、左右喷嘴这些只差一个字母的合并后，是 367 种。
- `device_hms`（对应上报里的 `hms` 列表）共 4697 条，大多是 AMS 各单元的重复。HMS 码第 9 到 12 位是级别（`0001` 致命、`0002` 严重、`0003` 一般、`0004` 提示，取自 pybambu），这里分别有 1434、3026、235 条。HMS 是「健康告警」，不卡住任务；需要人做决定的只看 `print_error`（见驱动草稿 §6.3）。
- `hms_action_20P.json` 只给 345 个码配了按钮。按钮 ID 在 Bambu Studio `DeviceErrorDialog.hpp` 里定义，屏幕上独有的按钮（比如异物报错的 `21`，实测就是「忽略并继续」）Studio 里没有。

## 1. 几条总原则

- 处理报错只能从打印机给出的选项里选。
- 暂停太久只提醒，不自动继续、不自动停止。
- 打印机在准备中、打印中、暂停中时，不下发新任务。

新提出、需要用户拍板的是 §3.1「daemon 自动清掉自己造成的残留报错」，以及 §3.2 的两个候选。

## 2. 第一类：下发前检查就能避免

这些报错都发生在「下发」这一刻或刚开打时，原因是下发时条件不满足。daemon 和面板在下发前检查就能挡住，不用等打印机报错。

| 检查项 | 能避免的报错（示例码） | 检查依据 |
| --- | --- | --- |
| 打印机没在跑任务 | `05004004` 设备忙、`0500C07F`、`0502C026` | `gcode_state` 不在 PREPARE / RUNNING / PAUSE。实测重复下发会被拒并留下 `05004004`（实测记录 §12） |
| 没在升级固件、传日志 | `05004005`、`05004030`、`05004009`、`05004012` | `upgrade_state.status` 不是 IDLE 就不发 |
| 存储在位、可写、有空间 | `05004006`、`0300800E` 文件不可用、`0500C010` U 盘读写异常、`0500402E` 文件系统不支持、`0500402F` 扇区损坏；HMS `0500_0100_0003_0004` U 盘空间不足 | `sdcard`（或 `home_flag & 0x100`）、`tl_external_free_kb`；按文件大小加录像预留算（实测记录 §6、§11） |
| 文件本身合法 | `05004002` 路径或文件名不支持、`0500400A` 文件名不支持、`05004003` / `0502402F` 解析失败、`05004046` 3MF 无效、`05004051` 圆弧拟合失败、`05004014` 切片失败 | 上传前在面板校验文件（文件名只用 ASCII、按机型复核） |
| 文件和机器匹配 | `05004037` 机型不符、`05004038` 喷嘴直径不符、`05004047` 热端数量或型号不符、`05008053` / `0500803C` 喷嘴设置不符、`05008057` / `05004057` 耗材需要更硬的喷嘴、`05008051` 板型不符 | 对照上报里的 `device.nozzle`、`device.extruder` 和切片里的 `printer_model_id`、`nozzle_diameters`、`filament` 硬度；板型拓竹不上报，只能由人确认 |
| AMS 状态 | `03004013` / `05004042` / `0502C010` AMS 正在烘干、`05024005` AMS 没标定、`07008029` 需要耗材切换器但离线 | 上报 `ams` 里的烘干和标定状态 |
| 没有未完成的操作 | `0502400E` 冷拉没做完、`0502400D` 进退料没做完 | 设备空闲但这些子流程没完成时不发 |
| 工具头是打印模式 | `05004070` / `0300804E` 装着激光或切割模块 | 上报 `device` 里的模块信息 |
| 固件版本一致 | `0580409C`、`05004031`、`05004033`、`050040A8`、`05004007` 固件不匹配或需要修复升级 | 定期 `get_version`；不一致的机器挂「阻止派单」 |
| 延时摄影和切片设置兼容 | `10014001` 螺旋花瓶、`10014002` 逐件打印不支持延时摄影，`10018003` / `10018004` / `1000C003` 延时摄影模式可能造成瑕疵 | 下发时按切片设置决定 `timelapse` 参数，不兼容就不开 |
| 下发流程本身 | 一次下发后没回执就重发，会自己制造 `05004004` | 下发后等回执或状态变化；超时先对账（看打印机是不是已经收到），不盲目重发 |

和云端、绑定相关的码（`0500401x`、`050140xx` 一类）在局域网模式下不会遇到，不用处理。

## 3. 第二类：可以由系统处理，不需要人到现场

### 3.1 daemon 自己造成的残留，自动清掉【待定，需要用户决定】

- `05004004`（设备忙）、`0502C026`（设备忙，无法操作）、`0500C07F`、`0502C012`（任务不能暂停）这类，是我们发的命令被拒后留下的。官方只配了「OK」按钮（`11`，即 `clean_print_error`），而且实测它会一直挂到打印结束以后（实测记录 §12）。
- 建议：daemon 识别出「是自己刚发的命令被拒」时，自动发一次 `clean_print_error`，只记日志、不挂等待处理、不通知人。下一次下发前，如果 `print_error` 是这几个码之一，也先清掉再发。
- 清掉的只是一个提示，不是替人选了处理报错的方式。

### 3.2 不涉及物理风险的软件类报错，候选自动处理【待定】

| 报错 | 官方按钮 | 候选做法 |
| --- | --- | --- |
| `07008012` / `07FE8012` 拿不到 AMS 映射表，「选 Resume 重试」 | `2`（继续） | 自动发一次 `resume` 重试；再失败才挂等待处理 |
| `0C008034` / `05008092` 实况或工具头摄像头初始化失败，「打印可以继续，部分 AI 功能不可用」 | `5`、`27` | 不自动处理。打印已经暂停，要不要在没有 AI 检测的情况下继续，由人决定，但可以标成「低风险」 |
| `0C008016` / `0C008018` / `0500807A` 异物检测功能不工作，「可以继续」 | `4`、`6` 或 `21` | 同上，标「低风险」，由人决定 |

### 3.3 只记录，不用处理

| 报错 | 含义 | 做法 |
| --- | --- | --- |
| `0300400C`、`0500400E` | 任务被取消 | 记「被人停止」，订单按停止处理（实测记录 §9） |
| `03008001` | 用户暂停 | 打印机进暂停中，不算报错，不需要人处理 |
| `1806C008` 一类 | AMS 断开，「重连后自动继续」 | 打印机自己会继续，面板只显示 |

## 4. 第三类：必须有人到现场，绝不自动处理

这些报错要么需要人动手（清东西、换料、拔管），要么需要人用眼睛判断（打印件有没有歪、能不能接着打）。自动继续可能撞坏喷嘴、在别人的件上接着打，或者浪费整盘料。全部由现场人员在面板上从打印机给的选项里选，同时带上报错时的照片。

| 大类 | 示例码 |
| --- | --- |
| 板上有东西、板没放好 | `0500806E` / `03008017` / `0C008017` 异物、`03008019` / `05008061` / `05004095` 没检测到板、`0500808C` / `0500809B` 板偏移、`03008014` 喷嘴被料包住或板装错 |
| 断料、进料、退料、切料 | `07008011` / `18008011` AMS 断料、`18FE8011` 外挂料用完、`07FF8030` 切片指定的料用完、`07008005` / `07008006` / `18058028` 进料失败、`07008003` / `07008004` 退料失败、`0300800B` / `18FE8002` 切刀卡住 |
| 堵头、挤出异常 | `03008016` / `03004006` 堵头、`0300800D` / `07008016` / `0300801C` / `0300801E` 挤出异常、`18008013` 冲刷旧料超时 |
| AI 检测到打印问题 | `03008003` 炒面、`05008099` 打印件移位或倒塌、`0C008043` 喷嘴结块、`0C008040` 空打、`0300800A` / `0C008005` 废料堆积 |
| 机械和运动 | `03004000` Z 轴回零失败、`03004009` XY 回零失败、`03004002` 自动调平失败、`0300800C` 丢步、`03008022` 热床下降受阻 |
| 门和外壳 | `03008042` / `0300800F` 门开着暂停、`03008005` / `05008040` 工具头前盖掉了 |
| 断电续打 | `03008007` 断电前有未完成的任务，`0300400D` 断电续打失败。断电重启过的机器，任务结局一律交给人判 |
| 摄像头脏或被挡 | `05008072` / `05008084` / `05008085` / `05008086` / `05008087` / `05008088` |

### 4.1 安全告警：最高级别

`0300806E`（喷嘴温控异常）、`0300806F`（热床异常升温）、`03008070`（腔体加热器异常升温）的官方文案都是「**立即断电，停止使用**」。这三个不能只挂等待处理，要：

- 面板最醒目地告警，通知所有在场管理员；
- 这台打印机自动停用，不再派单，直到有人检修后手动启用；
- 绝不提供「继续」。

`03008008` 喷嘴温度异常、`03008009` 热床温度异常、`03008018` 腔体温度异常、`0300400F` 电源电压不匹配也按同样的方式先停用、等人检查。

其他机型还有一组和火有关的码，同样按最高级别处理：`03008044`（腔内检测到火）、`0300C056`（检测到小火、自动灭火中止），以及灭火器缺失、失效、气瓶空（`0300807D` 到 `03008082`、`050040A1`）。后者不是正在发生的危险，但说明这台机器的自动灭火不可用，带激光模块的机型应该挂「阻止派单」。激光安全窗、急停按钮没装好（`0300804A`、`0300804B`、`03004042`）也一样。

## 5. 后续

- 拓竹会更新这些 JSON（文件里带 `ver`），daemon 应该随驱动一起内置，并记下版本。升级时对一下新增的码，看有没有落进「必须人处理」以外的类别。
- CSV 是关键词自动分类的，接入一个新机型前，至少把它的「安全告警」「下发前可避免」「系统可处理」三类人工过一遍。
- 第 3.1、3.2 节需要用户决定。
